# 0166 · Every blueprint is generated as a skeleton in CI, only when something that shapes it changed

- **Date:** 2026-10-15
- **Scenario:** "quero melhorar o CI do projeto para validar realmente a criacao de cada blueprint do projeto. Mas essa parte do CI so tem so deve ser disparada em algum alteracao que impact cada bleprint ou geracao do projeto"
- **Decision:** Option 1 — `.claude/.ci/BlueprintSkeletonTest.java` + `.github/workflows/blueprints.yml` + the `boundary-map` mode of `ArchHook.java` (Form 7c, with a `boundary_map` block in `extensions.json`)
- **State:** approved by Lucas Fernandes, on 2026-10-15

### Option 1 — skeleton test, path-filtered workflow, `boundary-map` mode (score 8)

**Motivator:** axis 17 — the gap is generation itself; the scope answer — deterministic.

**Pros:** each affected blueprint is generated for real, per build tool: the Initializr starter
(no dependencies, `javaVersion=21`), a reactor built from `modules[]` and `depends_on` (single-module
keeps the starter's layout), one `package-info.java` per `packages.map` role, the boundary map,
`ArchHook.java export`, then `./mvnw verify` or `./gradlew build` and `doctor gate` green inside the
project. Then, per `forbidden` entry (multi-module `forbidden_imports` and `dependency_rules`), one
class in `from` importing a type in `to`: `check` must exit 2 and `doctor gate` exit 1. The
single-module derivation of `project-files.md` § 5 stops being prose an agent runs: it becomes a
mode both `project-bootstrap` and the test call, so the test proves what generation does —
closing the "not proven" line of `0165`. A `plan` sub-command reads `git diff` and prints the
matrix: only paths under `.claude/blueprints/<id>/` → those ids; any other triggering path → all;
`workflow_dispatch` → all. The trigger `paths` list is the only list of "what shapes generation";
`plan` needs no second one.

**Cons:** the test writes its own minimal build files, not the agent's adaptation of
`templates/pom.*.xml.example` (`build-<tool>.md` § 4), and no feature dependency — those stay
unproven. In a multi-module blueprint the module a role's package goes to is inferred by the test
(module id equal to the role key with `.` → `-`, or its first segment, else the `contains_main`
module) — scaffold § 4.7 leaves it implicit. A Form 7c mode means a jar rebuild, and every change
to `ArchHook.java` triggers all 18 jobs (minutes of runner time, not a required check).

**Points cut in the rubric:** the two unproven parts above; the cost on `ArchHook.java` changes.

**CI:** new `.claude/.ci/BlueprintSkeletonTest.java` in new `.github/workflows/blueprints.yml`
(jobs `plan` and `skeleton`, matrix id × maven|gradle, `fail-fast: false`); new
`.claude/.ci/BoundaryMapTest.java` as a step of `validate` › `hooks-cross-platform` for the mode.

### Option 2 — the same test, deriving the map itself (score 6)

Same coverage, no new mode. The test holds a second copy of § 5 in Java, and the agent keeps
following the prose: the two diverge with nothing to notice — invariant 2, and the exact gap
`0165` recorded.

### Option 3 — end-to-end with the Claude CLI (score 3)

Proves the real path, prose included. Needs `ANTHROPIC_API_KEY` as a repository secret, costs per
run, 20-40 minutes per blueprint, is not deterministic, and `/init-project` asks transport and
SonarQube questions `claude -p` cannot answer — a non-interactive mode first. Rejected in the
interview.

### Option 4 — create nothing (score 2)

Nine blueprints, none ever generated by CI; the first broken one is found by a user.

**Found by the first run, not fixed here.** Without a git repository, `doctor`'s sweep walks the
tree and skips any directory named in `doctor.boundary_sweep.walk_exclude_dirs`, which lists `out`
(IntelliJ's output folder). Every `adapter/out/**` package of a hexagonal project — single- or
multi-module, since the package path is under `src/main/java` either way — is therefore not swept,
and `doctor gate` goes green over a forbidden import there. In a git repository the sweep reads
`git ls-files` and the gap does not exist, and the project's CI always runs in one; the test runs
`git init` for that reason, as `git-publish` leaves the project. A fix is its own decision (exclude
only a directory that is not under `src/`), with a case in `BoundarySweepTest`.

Not proven, and said so: the build files `project-bootstrap` writes from `templates/pom.*.xml.example`
and the feature dependencies — the test writes minimal build files of its own; a multi-module
role's module is inferred by the test (module id equal to the role with `.` → `-`, else its first
segment, else the `contains_main` module), as `scaffold.md` § 4.7 leaves it implicit; and the
agent's prose. Not run in GitHub Actions yet: the 18 combinations ran locally, the workflow itself
runs on this PR.
